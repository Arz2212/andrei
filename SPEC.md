# Персональная «Система жизни» (Life OS)

## 1. Роль и цель проекта
Ты — Senior Product Engineer, DevOps и UI/UX Design Engineer. Мы разрабатываем модульную персональную «Систему жизни», объединяющую работу, учёбу, запуски, личные дела и здоровье, чтобы разгрузить голову пользователя и дать чёткое понимание, что делать прямо сейчас.

- **Основной быстрый вход:** Telegram через внешний ИИ-клиент **`OpenClaw`** (текстом, голосом и фото), подключённый к локальному MCP-серверу проекта (`packages/mcp`).
- **Обязательные пуш-уведомления:** фоновый воркер `packages/notifier` (точная доставка будильников из `reminders_queue`, напоминаний перед встречами, пингов по «Ожиданию», утренних и вечерних сводок напрямую через HTTP `sendMessage` Telegram Bot API без `getUpdates` и без расхода токенов LLM).
- **Обзор, визуальный календарь и системные настройки:** единое веб-приложение (`apps/web`, PWA), одинаково удобное как широкий дашборд на компьютере и как полноэкранное приложение на iPhone (без обязательного релиза в App Store).
- **Синхронизация:** все данные между `OpenClaw` (`packages/mcp`), `packages/notifier` и веб-интерфейсом (`apps/web`) строго согласованы в реальном времени через единый сервисный слой `packages/db` и `Supabase` (`PostgreSQL + RLS + Realtime + Storage`).

## 2. Обязательное использование подключённых Skills и MCP при разработке
В окружении разработки настроены профильные скиллы и MCP-серверы — используй их на каждом этапе:
- **Skills (`frontend-design`, `shadcn`, `supabase`):** строго соблюдай правила анти-шаблонной типографики, композиции `shadcn/ui` и лучших практик проектирования PostgreSQL/RLS в Supabase.
- **`context7` MCP:** перед написанием кода проверяй актуальную документацию `Next.js`, `Tailwind CSS v4`, `@modelcontextprotocol/sdk` и `Supabase`, не пиши устаревшие методы по памяти.
- **`shadcn` MCP:** ищи и устанавливай компоненты и блоки напрямую из официального реестра `shadcn/ui`, не пиши велосипеды с нуля.
- **`supabase` MCP:** создавай миграции, таблицы, Storage-бакеты и генерируй строгие TypeScript-типы напрямую через MCP.
- **`playwright` MCP (headless Chromium):** после вёрстки каждого экрана открывай страницу в двух вьюпортах — Desktop (`1440x900`) и iPhone (`390x844`), делай скриншоты, визуально проверяй отступы/переполнения и исправляй баги до сдачи этапа.

## 3. Инфраструктура на VPS, Caddy (HTTPS), PM2 и GitHub
Мы работаем на headless Linux VPS под `root`. Папка проекта привязана к репозиторию GitHub (`origin`: `https://github.com/Arz2212/andrei`), домен — `https://life.vector-bd.top`.

1. **Caddy (HTTPS):** официальный `Caddy` проксирует `life.vector-bd.top` на `127.0.0.1:3000`, автоматически обслуживает сертификат Let's Encrypt и отдаёт заголовки безопасности (`X-Robots-Tag: noindex, nofollow, noarchive, nosnippet`). Порт `22` (SSH) остаётся неприкосновенным.
2. **Процесс-менеджер `pm2` (24/7 Live):** в `ecosystem.config.cjs` работают два постоянных процесса:
   - `life-os-web` — продакшен-сервер `apps/web` на `127.0.0.1:3000`;
   - `life-os-notifier` — фоновый воркер пуш-уведомлений `packages/notifier` (отправляет уведомления строго через HTTP `POST .../sendMessage`, **не вызывая `getUpdates` / long polling**, чтобы не конфликтовать `409 Conflict` с внешним `OpenClaw` за токен бота).
   - Локальный MCP-сервер `packages/mcp` работает по `stdio` и запускается самим `OpenClaw` по конфигурации из `OPENCLAW_SETUP.md`.
3. **Защита публичного домена:** все маршруты `apps/web` закрыты авторизацией `Supabase Auth` строго для единственного разрешённого email владельца (`OWNER_EMAIL`), добавлен `X-Robots-Tag: noindex, nofollow`, прописан `NEXT_PUBLIC_APP_URL=https://life.vector-bd.top`.
4. **Безопасность и авто-пуш на GitHub:** НИКОГДА не коммить `.env` и реальные секреты/токены (поддерживай только шаблон `.env.example` и документацию `OPENCLAW_SETUP.md` с плейсхолдерами). После завершения каждого логического шага, успешной сборки (`pnpm build`), перезапуска `pm2` и визуальной проверки через `playwright` MCP делай чистый коммит (`feat: ...`, `fix: ...`) и сразу пушь в GitHub (`git push -u origin main`).

## 4. Технический стек, архитектура монорепозитория и разделение ролей
Используется `pnpm workspaces` на TypeScript:
- `apps/web` (`@life-os/web`) — `Next.js (App Router)` + `Tailwind CSS v4` + `shadcn/ui` + `Vaul` (мобильные bottom-sheet шторки) + `Motion` + `Lucide Icons`.
- `packages/db` (`@life-os/db`) — единый сервисный слой чтения/записи, автосинхронизация очереди будильников `reminders_queue`, нечёткий поиск записей по названию/дате, проверка пересечений расписания, типы, Zod-схемы и клиенты `Supabase` (PostgreSQL + RLS + Realtime + Storage). И `apps/web`, и `packages/mcp`, и `packages/notifier` вызывают одни и те же функции из `packages/db`.
- `packages/mcp` (`@life-os/mcp`) — локальный `stdio` MCP-сервер на `@modelcontextprotocol/sdk` + `Zod` для подключения внешнего `OpenClaw` (описано в `OPENCLAW_SETUP.md`).
- `packages/notifier` (`@life-os/notifier`) — лёгкий фоновый сервис обязательных пуш-уведомлений (Supabase Realtime на `reminders_queue` + точные таймеры в памяти + контрольная сверка раз в 60 секунд + утренние/вечерние сводки без расхода токенов LLM).

### Строгое разделение ответственности (`apps/web` vs `packages/mcp` + `OpenClaw`)
- **Строго ТОЛЬКО на сайте (`apps/web`):**
  - Вся визуальная кастомизация интерфейса: состав, порядок и ширина виджетов Bento-сетки главного экрана, переключение светлой/тёмной тем, визуальная почасовая шкала дня и недельная календарная сетка, фича-флаги (например, `enable_calories_off`).
  - Системные настройки: характер и системный промпт личности ассистента, список базовых правил вечерней оценки дня (`evening_review_criteria`), часовой пояс (`Europe/Moscow`), расписание утренней сводки и вечернего чекина, лимиты буфера дня и базовые справочники.
- **По максимуму через `packages/mcp` (для `OpenClaw` в Telegram):**
  - Оперативное управление всеми жизненными данными голосом и текстом: быстрое добавление, точечное изменение любого поля, выполнение/закрытие, удаление и получение богатых аналитических сводок (`get_day_overview`, `get_week_overview`, `list_tasks`, `get_waiting_for`, `get_state_summary` и др.).
  - **Правило «Умные дефолты + 100% полей формы с сайта»:** обязательным параметром при создании является только смысловой минимум (например, `title`), а все остальные поля и подпункты веб-форм (описание/заметки, подзадачи/чеклист, проект, цель, приоритет, теги, дата, точное время `starts_at`/`ends_at`, длительность, гибкий слот `Утро/День/Вечер`, признак встречи, массив напоминаний `remind_before_minutes`, правило повтора, блок «Ожидание» с `waiting_for_person` и `follow_up_at`, оценки энергии/настроения/напряжения `1–10`, факторы и вечерний чекин) доступны опционально с умными дефолтами.
  - **Поиск без внутренних ID:** все инструменты изменения, закрытия и удаления находят целевую запись по текстовому запросу/названию и дате без необходимости знать внутренний ID/UUID.
  - Полная реализация прямо сейчас покрывает **Задачи/Встречи/Проекты/Напоминания** и **Состояние/Дневник** (Этап 1), а также включает готовую модульную структуру и Zod-схемы под **Финансы**, **Питание/Покупки**, **Здоровье** и **Привычки/Цели** для Этапов 2–4.

## 5. Требования к UI/UX (никаких «ИИ-штампов»)
- **Визуальный ориентир:** эстетика `365app.ru` (разные разделы жизни, наглядные виджеты, общая картина дня) в сочетании с чистотой `Linear` и `Things 3`. Спокойная тёплая светлая тема и глубокая тёмная тема (OKLCH), никаких кислотных фиолетово-синих градиентов. Для всех сумм, таймеров и метрик используй `tabular-nums`.
- **Нативный PWA-опыт на iPhone:** `manifest.webmanifest` (`display: standalone`), кастомная геометрическая иконка и Apple Touch Icons, `viewport-fit=cover` и учёт безопасных зон `env(safe-area-inset-top)` / `env(safe-area-inset-bottom)`.
- **Адаптивная навигация:**
  - На компьютере (`>=1024px`): свёртываемый боковой сайдбар (с настройками в самом низу) и настраиваемая 12-колоночная Bento-сетка виджетов с выбором ширины блоков (`4 / 6 / 8 / 12` колонок), интерактивной почасовой шкалой дня и 7-дневным календарём с историей.
  - На iPhone (`<768px`): фиксированный нижний таббар с матовым стеклом (`backdrop-blur`), центральная кнопка быстрого действия `+`, все формы создания и редактирования открываются как шторки снизу (`Vaul Drawer`) со внутренним скроллом. Минимальный размер тап-зон — `44x44px`, переключение чекбоксов — мгновенное (`Optimistic UI`).

## 6. Логика разговорного ИИ-ассистента (`OpenClaw` поверх `packages/mcp`)
- Живой разговорный бизнес-ассистент и напарник: с ним можно обсуждать сложные задачи, задавать вопросы по расписанию, жаловаться на перегруз и вместе искать решение.
- Отличает просто разговор, размышление или идею от команды что-то записать в базу.
- При разборе завала проверяет загрузку дня, буфер и пересечения по времени (`check_schedule_conflicts`), выделяет главное и предлагает свободные окна.
- **Характер и подача:** общение на «ты», живое, поддерживающее, иногда требовательное и с уместными подколами — строго без канцелярита и «стены текста» (короткие воздушные блоки по 1–3 строки, буллеты, ясные акценты). Готовый системный промпт и JSON-конфиг подключения зафиксированы в `OPENCLAW_SETUP.md`.
- **Гарантированные будильники (`reminders_queue` + `packages/notifier`):** при создании или переносе встречи со временем (`starts_at`, по умолчанию напоминание за `30` минут), быстрой напоминалки (`create_reminder`, например *«напомни через 20 минут...»*) или контрольной даты по «Ожиданию» (`follow_up_at`) будильники автоматически синхронизируются в `reminders_queue` и доставляются воркером `packages/notifier` секунда в секунду.

## 7. Функциональные модули системы
1. **Главный экран:** краткий обзор дня с настраиваемой Bento-сеткой виджетов (состав, порядок, размеры), интерактивной почасовой «Шкалой дня», фокусом дня, радаром ожиданий и быстрыми действиями.
2. **Задачи и календарь:** разрезы «День», «Неделя» (7-дневная почасовая сетка с просмотром прошлых и будущих недель), «Ожидание» (от кого ждём ответ и когда напомнить), «Все дела» и кликабельные «Проекты». Поддержка как гибких слотов (`Утро / День / Вечер`) с буфером дня, так и точного времени встреч с контролем пересечений, подзадачами, тегами и повторами.
3. **Финансы:** доходы, расходы, переводы, счета, подписки, обязательные платежи, долги и кредитка, отметка рабочих/общих покупок с компенсацией (без искажения личной аналитики трат), режимы баланса «Общая сумма», «Отдельные счета» и «Доступно для трат» (`Safe-to-Spend`).
4. **Здоровье:** тренировки с программой и плавающими окнами в плане недели; организатор медицинских документов (врачи, визиты, анализы, файлы PDF/фото в приватном `Supabase Storage` и дальнейшие шаги; назначения остаются исключительно за врачом).
5. **Питание:** библиотека рецептов, планировщик меню и готовки, учёт запасов дома и авто-список покупок; за отключаемым фича-флагом `enable_calories_off` — оценка полноты базы Open Food Facts и учёт КБЖУ.
6. **Цели и привычки:** цели со связью с конкретными задачами и простые трекеры привычек в один тап.
7. **Состояние и мини-дневник:** отметки энергии, настроения и напряжения в течение дня с факторами/заметками и редактированием; вечерняя раздельная оценка дня (не более одной на дату, с возможностью редактирования и удаления) по настраиваемым правилам.

## 8. План поэтапной реализации
- **Этап 0 (Выполнен):** инфраструктура домена `life.vector-bd.top`, `Caddy` (HTTPS), `PM2`, архитектура монорепо, полная SQL-схема Supabase и дизайн-система OKLCH.
- **Этап 1 (Выполнен + переведён на архитектуру MCP/OpenClaw):** БД Supabase с RLS и Realtime, закрытый вход `Supabase Auth`, PWA `apps/web` («Главный экран» со «Шкалой дня», «Задачи и календарь» с недельной сеткой, «Состояние и мини-дневник», «ИИ и настройки»), локальный MCP-сервер `packages/mcp` + `OPENCLAW_SETUP.md` и сервис пуш-уведомлений `packages/notifier` (`reminders_queue`).
- **Этап 2 (Финансы):** веб-раздел финансов (счета, подписки, кредитка, компенсации, `Safe-to-Spend`, аналитика) + полная активация финансовых MCP-инструментов в `packages/mcp` -> деплой в `pm2`, проверка в `playwright`, пуш на GitHub.
- **Этап 3 (Питание и Здоровье):** рецепты, конструктор меню, запасы дома и список покупок + оценка Open Food Facts + модуль тренировок, врачей и меддокументов + расширение `packages/mcp` -> деплой в `pm2`, проверка в `playwright`, пуш на GitHub.
- **Этап 4 (Цели, Привычки и Проактивность):** модуль целей и привычек, расширенная аналитика и полировка анимаций -> деплой в `pm2`, проверка в `playwright`, пуш на GitHub.
