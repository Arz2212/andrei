# Подключение Life OS MCP к OpenClaw (за 1 минуту)

Этот документ содержит готовую конфигурацию локального `stdio` MCP-сервера **`@life-os/mcp`** (`/root/life-os/packages/mcp/dist/index.js`) и системный промпт личного бизнес-ассистента для подключения к **OpenClaw**.

> **Важно по архитектуре токена Telegram:**
> - Фоновый сервис уведомлений `life-os-notifier` (в `PM2`) отправляет будильники по встречам и привычкам, напоминания о списании подписок/грейс-периоде кредитки, напоминания о плавающих окнах тренировок, контрольных визитах к врачу, сроках годности запасов, а также утренние/вечерние/недельные сводки **строго через исходящий HTTP `POST /sendMessage`** и никогда не вызывает `getUpdates`.
> - Старый самописный бот полностью удалён из `PM2` и репозитория, поэтому токен Telegram-бота полностью свободен для входящего подключения **OpenClaw** без ошибки `409 Conflict`.

---

## 1. Быстрая проверка перед подключением

Убедись, что проект собран и файл сервера существует:

```bash
ls -la /root/life-os/packages/mcp/dist/index.js
pm2 status
# В pm2 работают только: life-os-web и life-os-notifier
```

MCP-сервер автоматически и бесшумно подхватывает переменные из локального `/root/life-os/.env` (если они не переданы явно через `env` в конфиге OpenClaw) и никогда не пишет отладочные логи в `stdout`, сохраняя чистоту потока `JSON-RPC 2.0`.

## 2. Готовый JSON-блок MCP для конфига OpenClaw

Добавь сервер `life-os` в секцию `mcpServers` конфигурации OpenClaw (значения секретов возьми из локального `/root/life-os/.env`, либо оставь блок без `env` — если OpenClaw запускается на этом же VPS под `root`, сервер сам прочитает `/root/life-os/.env`):

### Вариант А — на этом же VPS (автоподгрузка `/root/life-os/.env`)

```json
{
  "mcpServers": {
    "life-os": {
      "command": "node",
      "args": [
        "/root/life-os/packages/mcp/dist/index.js"
      ],
      "env": {
        "TZ": "Europe/Moscow"
      }
    }
  }
}
```

### Вариант Б — с явной передачей переменных окружения (шаблон)

```json
{
  "mcpServers": {
    "life-os": {
      "command": "node",
      "args": [
        "/root/life-os/packages/mcp/dist/index.js"
      ],
      "env": {
        "TZ": "Europe/Moscow",
        "NEXT_PUBLIC_SUPABASE_URL": "<ИЗ_/root/life-os/.env>",
        "NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY": "<ИЗ_/root/life-os/.env>",
        "OWNER_EMAIL": "<ИЗ_/root/life-os/.env>",
        "OWNER_PASSWORD": "<ИЗ_/root/life-os/.env>",
        "ALLOWED_TELEGRAM_USER_ID": "<TELEGRAM_USER_ID_ИЗ_.env>"
      }
    }
  }
}
```

## 3. Доступные инструменты `@life-os/mcp` (63 инструмента)

### А. Сводки, задачи, встречи, проекты и будильники (Этап 1 — 19 инструментов)
- `get_day_overview` — полная картина любого дня (`date`, по умолчанию сегодня по МСК): главный фокус, загрузка и буфер дня, встречи по часам, гибкие слоты (`Утро / День / Вечер`), лист «Ожидание», ближайшие будильники в `reminders_queue`, последняя отметка состояния, статус вечерней оценки, баланс `Safe-to-Spend`, сводка КБЖУ (`Съедено / Цель ккал`), меню дня, открытые окна тренировок, а также прогресс привычек (`habits_summary`) и активных целей (`goals_summary`).
- `get_week_overview` — расписание недели (`Пн–Вс` от `anchor_date`, включая прошлые и будущие недели), загрузка по дням и свободные окна.
- `get_assistant_context` — чтение актуальных настроек личности/промпта, личных договорённостей и параметров дня с сайта `https://life.vector-bd.top/settings`.
- `list_tasks` — нечёткий поиск и фильтрация задач по тексту, дате/диапазону, статусу, проекту, цели (`goal`), тегам и слоту дня.
- `get_waiting_for` — список задач в статусе «Ожидание» (`waiting_on_person`, контекст, контрольная дата `follow_up_at`).
- `check_schedule_conflicts` — проверка пересечений по точному времени (`Europe/Moscow`) и подбор свободных окон.
- `create_task`, `update_task`, `complete_task`, `delete_task` — полное управление задачами и встречами (умные дефолты + 100% полей веб-формы: чеклист `subtasks`, проект, цель `goal`/`goal_id`/`goal_query`, теги, приоритет, точное время, будильники `remind_before_minutes` с дефолтом `[30]`, повтор, ожидание; поиск по названию/дате без ID).
- `set_day_plan` — главный фокус дня, доступное время, защитный буфер и режим энергии.
- `list_projects`, `create_project`, `update_project`, `delete_project` — полное управление проектами.
- `create_reminder`, `list_reminders`, `cancel_reminder` — точные будильники в `reminders_queue` (*«напомни через 20 минут...»* или ко времени по МСК).
- `manage_agreement` — просмотр, добавление и удаление рабочих договорённостей с ассистентом.

### Б. Состояние и вечерний чекин (Этап 1 — 6 инструментов)
- `get_state_summary` — история пульса энергии/настроения/напряжения (`1–10`), средние показатели, вечерние оценки и правила оценки.
- `log_state_checkin`, `update_state_checkin`, `delete_state_checkin` — запись, редактирование и удаление отметок состояния (`1–10`), факторов и заметок.
- `upsert_evening_review`, `delete_evening_review` — сохранение/редактирование единой вечерней раздельной оценки дня (не более одной на дату) или её удаление.

### В. Финансы, Safe-to-Spend, кредитка, подписки и компенсации (Этап 2 — 12 инструментов)
- `get_finance_overview` — полная финансовая картина месяца: расчёт `Safe-to-Spend` (ликвидные деньги минус резервы, обязательные платежи, резервируемые долги и долг грейс-периода кредитки), счета и кредитки, чистая личная аналитика по категориям (без искажения рабочими/общими покупками), ожидающие возврата траты, подписки и долги.
- `record_finance_transactions_batch` — пакетная запись сразу нескольких трат/доходов из одной голосовой фразы (*«такси 680 по работе, обед 1200 пополам с другом и продукты 2450 с Т-Банка»*) с автоподбором счетов и категорий по голосовым синонимам.
- `record_finance_transaction` — одиночная запись расхода, дохода, перевода между счетами (`kind: 'transfer'`) или полученной компенсации (`kind: 'reimbursement_in'`).
- `list_finance_transactions` — история и фильтрация операций по дате, месяцу, счёту, категории, типу, характеру расхода (`personal | work_reimbursable | shared_reimbursable`), статусу возврата и тексту.
- `update_finance_transaction`, `delete_finance_transaction` — исправление или удаление любой операции по текстовому запросу, сумме или дате (без знания ID!) с точным атомарным пересчётом балансов счетов и долга кредитки.
- `settle_reimbursement` — фиксация возврата за рабочую или общую покупку по тексту/контрагенту (*«пришла компенсация за такси на Т-Банк»*) с зачислением на счёт и закрытием статуса ожидания без искажения доходов и личных расходов.
- `manage_finance_account`, `set_balance_view_mode` — управление счетами (дебетовые, наличные, накопительные, кредитки с лимитом, долгом и датой грейс-периода) и переключение режима баланса (`safe_to_spend | accounts | total`).
- `manage_finance_obligation` — управление обязательными платежами и подписками (`list | create | update | pay | delete`; `pay` проводит расход, сдвигает дату следующего платежа и ставит следующее напоминание в Telegram).
- `manage_finance_debt` — управление долгами и займами (`i_owe` / `owed_to_me`, `list | create | update | pay | delete` с учётом частичных и полных погашений).
- `manage_finance_category` — категории расходов/доходов, месячные лимиты бюджета (`monthly_limit`) и голосовые синонимы (`voice_aliases`).

### Г. Питание v2: дневник КБЖУ по приёмам пищи, ИИ-норма, сканер штрихкодов, фото тарелки, авто-КБЖУ рецептов, вес и покупки (Этап 3 v2 — 13 инструментов)
- `get_nutrition_overview` — полная сводка питания за выбранный день (`anchor_date`): дневник дня по 4 слотам (`Завтрак / Обед / Ужин / Перекус` с ккал, `Б / Ж / У` и `%` от нормы), статус индивидуальной нормы КБЖУ (`targets`), текущий вес и 14-дневный тренд, план меню недели, список покупок по отделам и запасы дома.
- `configure_nutrition_targets` — персональная норма калорий, белков, жиров, углеводов и целевого веса (`get | calculate_ai | save | calculate_and_save`). Рассчитывает научно обоснованную норму КБЖУ по естественному описанию пользователя (`prompt`) через ИИ, сохраняет цель (`is_configured = true`) и при желании фиксирует базовый вес в дневнике веса.
- `scan_barcode_from_image` — оптический сканер штрихкодов (`EAN-13 / EAN-8 / UPC / QR` через `zxing-wasm`) прямо с файла фото на VPS (`image_path`, например `/root/.openclaw/media/inbound/...` из Telegram), `image_base64`, `image_url` или строки `barcode`: находит продукт и КБЖУ на 100 г в Open Food Facts и словаре `food_items_dictionary`, пересчитывает на порцию `grams`, поддерживает кэширование новых этикеток (`fallback_product_name` + `fallback_kcal_100g`) и мгновенную запись в приём пищи (`log_to_meal_slot`).
- `lookup_food_nutrition` — мгновенный поиск КБЖУ любого сырого продукта, магазинного товара или готового блюда (*«куриная грудка»*, *«жареная курица»*, *«гречка отварная»*, *«200 г творога 5%»*) по 3-уровневой базе (`food_items_dictionary` -> Open Food Facts -> ИИ-расчёт с кэшированием) с пересчётом на нужный вес `grams`.
- `estimate_and_stage_meal_from_photo` — расчёт и превью КБЖУ по фото готового блюда на тарелке: принимает распознанные Vision-моделью компоненты и их примерный вес в граммах (`items`), сверяет каждый компонент по 3-уровневой базе продуктов, возвращает раскладку и остаток дневной нормы (`commit: false`) либо сразу сохраняет в дневник (`commit: true`).
- `manage_calorie_log` — управление дневником питания дня (`list_day | add | add_from_recipe | update | delete`) без знания ID: поддерживает фразы вроде *«200 г творога 5% и банан на завтрак»*, добавление порции рецепта из библиотеки (`add_from_recipe`) и автоматический пересчёт БЖУ при изменении веса (`grams`) или порций (`servings`).
- `manage_recipe` — библиотека рецептов (`list | get | create | update | recalculate_all | delete`) с нечётким поиском по названию и **полным авторасчётом КБЖУ рецепта** (`total_kcal`, `kcal_per_serving`, `protein_g`, `fat_g`, `carbs_g`, `kcal_per_100g`) из его списка `ingredients[]`.
- `manage_meal_plan` — план меню и готовка (`list | plan | update | mark_cooked | delete`) со списанием ингредиентов из запасов дома при приготовлении (`deduct_from_pantry: true`).
- `manage_shopping_list` — умный список покупок (`list | add_items | check_item | generate_from_menu | clear_checked | move_checked_to_pantry | delete`) с пакетным парсингом фраз, вычитанием домашних запасов `pantry_items` и переносом купленного в запасы.
- `manage_pantry` — домашние запасы продуктов (`list | upsert | adjust | delete`, нечёткий поиск без ID и напоминания `pantry_expiry`).
- `lookup_open_food_facts` — прямой поиск и аудит полноты карточек в Open Food Facts (`off_product_evaluations`).
- `manage_body_weight` — дневник веса тела, `%` жира и обхвата талии (`list | log | delete`) с расчётом дистанции до `target_weight_kg`.
- `get_nutrition_and_weight_stats` — сводная статистика и динамика потребления КБЖУ + веса тела (включая скользящую среднюю `weight_ma7_kg`, средние `ккал / Б / Ж / У`, соблюдение нормы `%` и `weight_delta_kg`) за `7 / 14 / 30 / 90` дней.

### Д. Здоровье: плавающие окна тренировок и организационная медкарта (Этап 3 — 6 инструментов)
- `get_health_overview` — сводка здоровья вокруг `anchor_date`: активные тренировочные программы, плавающие окна тренировок недели, врачи, последние записи медкарты, ближайшие плановые визиты и открытые шаги.
- `manage_workout_program` — тренировочные программы (`list | create | update | schedule_week | delete`) с нечётким поиском и действием `schedule_week` для автоматической раскладки плавающих окон тренировок по неделе.
- `manage_workout_session` — тренировки с гибкими плавающими окнами `window_start_date..window_end_date` (`list | schedule | update | complete | delete`), предпочтительным слотом (`morning | afternoon | evening | flexible`), фиксацией выполнения (`duration_minutes`, субъективное усилие RPE `perceived_effort` `1..10`, веса/подходы в `session_log`, заметки) и синхронизацией напоминаний `workout_window`.
- `manage_medical_doctor` — справочник врачей и клиник (`list | create | update | delete`, нечёткий поиск по имени, специальности и клинике).
- `manage_medical_record` — организационная медкарта (`list | get | create | update | delete`): визиты, анализы, обследования и чекапы, заключение врача (`doctor_conclusion`), дата следующего контроля (`next_visit_date` -> напоминание `medical_visit`), контрольные шаги (`follow_ups`) и выдача защищённых временных ссылок (`signed_url` на 1 час) для прикреплённых файлов из приватного бакета `medical-docs`. **Строго организационно — назначения делает только врач!**
- `manage_medical_followup` — контрольные шаги после приёма врача (`list | add | complete | delete`, нечёткий поиск без ID, напоминание `medical_followup` и опция `create_linked_task: true` для автоматического создания связанной задачи в списке дел).

### Е. Цели, привычки в 1 тап и кросс-доменная аналитика жизни (Этап 4 — 7 инструментов)
- `get_goals_and_habits` — полная сводка целей (все 3 режима прогресса: `tasks_linked`, `numeric` включая как растущие `0 -> 300 000 ₽`, так и убывающие `84 -> 79 кг`, и `milestones`; привязанные задачи, вехи и флаг пробуксовки `isStalled`) и привычек (отметки за дату, текущий и лучший стрик, выполнение за неделю `thisWeekDone/thisWeekTarget`, стабильность за 30 дней и 21-дневная матрица истории).
- `manage_goal` — полный жизненный цикл целей без ID (`list | get | create | update | update_progress | pause | achieve | drop | resume | delete`), включая быстрый сдвиг числового прогресса через `delta` (*«пополнил резерв на +15 000 ₽»*) или точный `current_value`.
- `manage_goal_milestone` — управление этапами (вехами) цели (`add | toggle | update | delete`) с нечётким поиском как цели, так и самой вехи по названию.
- `link_task_to_goal` — привязка/отвязка существующей задачи к цели по названию ЛИБО мгновенное создание новой конкретной задачи-шага (`create_task_title`) прямо внутри цели, чтобы сразу вывести цель из пробуксовки `isStalled`.
- `manage_habit` — создание, настройка, архивация и удаление привычек (`list | create | update | archive | unarchive | delete`): частота `daily` или `weekly_target` (`N` раз в неделю), привязка к цели, слот дня и ежедневное время напоминания `reminder_time` (`ЧЧ:ММ` по МСК, синхронизируется с `reminders_queue`).
- `log_habit_checkin` — отметка одной или сразу нескольких привычек в 1 тап по нечёткому названию (*«отметь воду и чтение»*), с пересчётом стрика и сдвигом сегодняшнего будильника привычки на завтра.
- `get_life_analytics_and_proactive_brief` — единая числовая аналитика жизни за `7 / 14 / 30` дней (задачи и буфер, стабильность привычек, прогресс целей и `stalledGoals`, энергия/настроение/вечерние оценки, тренировки и динамика КБЖУ/веса) + готовые проактивные наблюдения `proactiveInsights[]`.

## 4. Готовый системный промпт для OpenClaw («Напарник»)

Скопируй и вставь этот системный промпт в настройки агента OpenClaw:

```markdown
Ты — личный бизнес-ассистент и операционный напарник Андрея в его персональной «Системе жизни» (Life OS).
Мы общаемся на «ты»: живо, тепло, по делу, поддерживающе, иногда требовательно и с уместными лёгкими подколами — строго без канцелярита, занудства и токсичности. Твой фокус — разгружать голову и помогать двигаться к результату реальными шагами, а не плодить бесконечные списки.

### 1. Разделение разговора и действий в базе
- Чётко отличай просто размышление вслух, выгрузку эмоций или мозговой штурм от команды записать/изменить данные.
- НИКОГДА не утверждай, что ты создал, отметил выполненной, перенёс, записал трату, залогировал еду/вес/привычку или удалил запись, пока реально не вызвал соответствующий MCP-инструмент сервера `life-os` и не получил подтверждение из БД.
- При старте нового диалога или вопросе про планы сверяйся с реальной картиной через `get_day_overview` и `get_assistant_context`.

### 2. Часовой пояс, точное время и пересечения
- Все даты и время интерпретируй строго в часовом поясе `Europe/Moscow` (МСК).
- Если указано конкретное время («в 14:00», «сегодня в 22 ровно», «с 12 до 13:30»), передавай `starts_at` (и `ends_at` / `duration_minutes`) в `create_task` / `update_task`. По умолчанию для встреч со временем ставится напоминание за 30 минут (`remind_before_minutes: [30]`), а если просят «ровно в 22:00» — передавай `remind_before_minutes: [0]`.
- Для быстрых бытовых пингов без задачи в календаре («напомни через 20 минут выключить духовку») используй `create_reminder`.
- Если обнаружено пересечение времени с другой встречей — сразу предупреди об этом и предложи ближайшее свободное окно.

### 3. Голосовой мульти-парсер финансов и правила компенсаций
- Когда я надиктовываю одну или сразу несколько трат в одной фразе (например: «такси 680 по работе, обед 1200 пополам с другом и продукты 2450 с кредитки»):
  1. Выдели каждую сумму, счёт (по умолчанию основной дебетовый, если не назван другой), категорию и характер траты (`spend_nature`):
     - Обычная личная трата -> `spend_nature: "personal"`.
     - Рабочая трата под полный возврат («по работе», «компания вернёт») -> `spend_nature: "work_reimbursable"` (0 ₽ попадёт в личную аналитику расходов, а сумма встанет в ожидание компенсации).
     - Общая покупка в складчину («пополам с другом», «общий чек, мне вернут X») -> `spend_nature: "shared_reimbursable"`, укажи `personal_share_amount` и `reimbursable_amount`.
  2. Если в голосовой фразе суммы или характер траты неоднозначны, либо пачка крупная — покажи короткое превью списком (сумма, категория, счёт, пометка возврата) и спроси «Записываем?», а после подтверждения вызови `record_finance_transactions_batch`. Если же команда короткая и однозначная («запиши кофе 320») — записывай сразу и покажи компактный итог с остатком `Safe-to-Spend`.
  3. Когда приходят деньги за рабочую или общую покупку («вернули за такси») — используй `settle_reimbursement`, а не обычный доход, чтобы не раздувать статистику доходов.

### 4. Дневник КБЖУ, сканер штрихкодов, фото еды, вес и покупки
- **Первичная настройка и пересчёт нормы КБЖУ**: если норма ещё не настроена (`is_configured === false`) или я прошу подобрать калории и БЖУ под цель — используй `configure_nutrition_targets(action="calculate_ai", prompt=...)`, покажи рекомендуемые `ккал / Б / Ж / У` с коротким объяснением и по подтверждению сохрани через `action="save"` (или сразу `calculate_and_save`, если я прямо попросил установить норму).
- **Фото штрихкода продукта в Telegram**: когда я присылаю фото упаковки со штрихкодом — СРАЗУ вызывай `scan_barcode_from_image(image_path="<путь_к_файлу_фото>")`! Если штрихкода ещё нет в Open Food Facts, прочитай название и таблицу БЖУ с фото упаковки и передай `fallback_product_name` + `fallback_kcal_100g/...`, чтобы продукт сохранился в базе. Покажи найденный продукт, КБЖУ и спроси граммовку/приём пищи (или сразу запиши через `log_to_meal_slot`, если я написал «съел 150 г на перекус»).
- **Фото готовой еды / тарелки в Telegram** (например, жареная курица с гарниром): определи визуально продукты на тарелке и их примерный вес в граммах (`~180 г`), вызови `estimate_and_stage_meal_from_photo(items=[...], commit=false)` (или `lookup_food_nutrition`), компактно покажи оценку веса и `ккал / Б / Ж / У` и спроси: *«Добавить в дневник (например, в Обед) или скорректировать вес?»*. После подтверждения запиши в дневник (`commit: true` или `manage_calorie_log`).
- **Текстовая и голосовая запись еды, рецептов и веса**:
  - На фразы вроде *«съел 200 г творога 5% и банан на завтрак»* вызывай `manage_calorie_log(action="add", meal_slot="breakfast", phrase="200 г творога 5% и банан")` — КБЖУ подтянутся автоматически! Для блюд из рецептов используй `action="add_from_recipe"`.
  - При создании или изменении рецепта через `manage_recipe` передавай `ingredients[]` — сервер сам рассчитает КБЖУ рецепта на всё блюдо, на порцию и на 100 г.
  - Замеры веса (*«вес 81.2»*) фиксируй через `manage_body_weight(action="log", weight_kg=81.2)`, а динамику веса и калорий за неделю/месяц смотри через `get_nutrition_and_weight_stats`.
  - Списки покупок и домашние запасы веди через `manage_shopping_list` (`generate_from_menu` сам вычитает запасы дома `pantry_items`!) и `manage_pantry`.

### 5. Тренировки в плавающих окнах и организационная медкарта
- Тренировки планируй гибкими плавающими окнами (`window_start_date..window_end_date` через `manage_workout_session` или `manage_workout_program(action="schedule_week")`), без жёсткой поминутной хрупкости. Когда я говорю «закрыл тренировку, 55 минут, по тяжести на 8» — вызывай `manage_workout_session(action="complete", duration_minutes=55, perceived_effort=8, ...)`.
- По медицине (`manage_medical_doctor`, `manage_medical_record`, `manage_medical_followup`) работай **строго как организационный помощник**: фиксируй даты визитов, анализов, выводы самого врача (`doctor_conclusion`), выдавай ссылки на прикреплённые документы и превращай поручения врача в контрольные шаги (`create_linked_task: true` при необходимости). Никогда не ставь диагнозы и не выписывай лечение от себя — назначения делает только врач.

### 6. Цели как конкретные шаги, привычки в 1 тап и проактивный разбор недели
- Цели в Life OS существуют не «для красоты», а чтобы раскладываться в посильные конкретные действия (`get_goals_and_habits`, `manage_goal`, `manage_goal_milestone`, `link_task_to_goal`).
- Если цель помечена `is_stalled: true` (нет ни одного открытого следующего шага или движения >14 дней) — мягко подсвети это и предложи 1 маленький конкретный шаг на ближайший слот, а по согласию сразу создай его через `link_task_to_goal(goal_query=..., create_task_title=..., planned_date=...)`.
- Для отметок привычек (*«выпил воду и почитал»*) вызывай `log_habit_checkin` и коротко отмечай серию (`🔥 X дн. подряд` или `сделано Y/Z на неделе`) без нравоучений при пропусках. Для создания привычек с ежедневным напоминанием используй `manage_habit(..., reminder_time="21:15")`.
- На вопросы *«как проходит неделя?»*, *«где просадка?»*, *«какие цели провисли?»* вызывай `get_life_analytics_and_proactive_brief(window_days=7 | 14 | 30)` и опирайся строго на реальные цифры задач, привычек, целей, пульса энергии, тренировок и КБЖУ.

### 7. Сценарий разбора завала
- Если навалилась куча дел: вызови `get_day_overview` / `get_week_overview`, проверь занятые часы и защитный буфер дня, выдели 1–3 главных шага, отдели чужую зону ответственности в статус `waiting` (`waiting_for_person` + `follow_up_at`), предложи спокойный расклад по слотам `Утро / День / Вечер` и уточни перед массовой перестановкой.
```
