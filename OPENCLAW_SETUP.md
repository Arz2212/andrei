# Подключение Life OS MCP к OpenClaw (за 1 минуту)

Этот документ содержит готовую конфигурацию локального `stdio` MCP-сервера **`@life-os/mcp`** (`/root/life-os/packages/mcp/dist/index.js`) и системный промпт личного бизнес-ассистента для подключения к **OpenClaw**.

> **Важно по архитектуре токена Telegram:**
> - Фоновый сервис уведомлений `life-os-notifier` (в `PM2`) отправляет будильники и утренние/вечерние сводки **строго через исходящий HTTP `POST /sendMessage`** и никогда не вызывает `getUpdates`.
> - Старый самописный бот полностью удалён из `PM2` и репозитория, поэтому токен Telegram-бота полностью свободен для входящего подключения **OpenClaw** без ошибки `409 Conflict`.

---

## 1. Быстрая проверка перед подключением

Убедись, что проект собран и файл сервера существует:

```bash
ls -la /root/life-os/packages/mcp/dist/index.js
pm2 status
# В pm2 работают только: life-os-web и life-os-notifier
```

MCP-сервер автоматически и бесшумно подхватывает переменные из локального `/root/life-os/.env` (если они не переданы явно через `env` в конфиге OpenClaw) и никогда не пишет отладочные логи в `stdout`, сохраняя чистоту потока `JSON-RPC 2.0`.

---

## 2. Готовый JSON-блок MCP для конфига OpenClaw

Добавь сервер `life-os` в секцию `mcpServers` конфигурации OpenClaw (значения секретов возьми из локального `/root/life-os/.env`, либо оставь блок без `env` — если OpenClaw запускается на этом же VPS под `root`, сервер сам прочитает `/root/life-os/.env`):

### Вариант А — на этом же VPS (автоподгрузка `/root/life-os/.env`)

```json
{
  "mcpServers": {
    "life-os": {
      "command": "node",
      "args": [
        "/root/life-os/packages/mcp/dist/index.js"
      ],
      "env": {
        "TZ": "Europe/Moscow"
      }
    }
  }
}
```

### Вариант Б — с явной передачей переменных окружения (шаблон)

```json
{
  "mcpServers": {
    "life-os": {
      "command": "node",
      "args": [
        "/root/life-os/packages/mcp/dist/index.js"
      ],
      "env": {
        "TZ": "Europe/Moscow",
        "NEXT_PUBLIC_SUPABASE_URL": "<ИЗ_/root/life-os/.env>",
        "NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY": "<ИЗ_/root/life-os/.env>",
        "OWNER_EMAIL": "<ИЗ_/root/life-os/.env>",
        "OWNER_PASSWORD": "<ИЗ_/root/life-os/.env>",
        "ALLOWED_TELEGRAM_USER_ID": "1479912341"
      }
    }
  }
}
```

## 3. Доступные инструменты `@life-os/mcp`

### Сводки, чтение и контекст
- `get_day_overview` — полная картина любого дня (`date`, по умолчанию сегодня по МСК): главный фокус, загрузка и буфер дня, встречи по часам, гибкие слоты (`Утро / День / Вечер`), лист «Ожидание», ближайшие будильники в `reminders_queue`, последняя отметка состояния, статус вечерней оценки и баланс `Safe-to-Spend`.
- `get_week_overview` — расписание недели (`Пн–Вс` от `anchor_date`, включая прошлые и будущие недели), загрузка по дням и свободные окна.
- `list_tasks` — гибкая выборка и нечёткий поиск задач по тексту, дате/диапазону, статусу (`inbox | todo | in_progress | waiting | done`), проекту, тегам и слоту дня.
- `get_waiting_for` — список всех задач в статусе «Ожидание» (`waiting_on_person`, контекст, контрольная дата `follow_up_at`).
- `check_schedule_conflicts` — проверка пересечений по точному времени (`Europe/Moscow`) и подбор свободных окон на выбранный день.
- `get_state_summary` — сводка пульса энергии/настроения/напряжения за период, вечерние оценки дня и активные правила оценки с сайта.
- `get_assistant_context` — чтение актуальных настроек личности/промпта, личных договорённостей и параметров дня, заданных на сайте `https://life.vector-bd.top/settings`.

### Задачи, встречи, проекты и будильники (Умные дефолты + 100% полей с сайта)
- `create_task` — создание задачи или встречи (обязателен только `title`; опционально доступны описание, чеклист `subtasks`, проект по названию или ID, цель, приоритет `1..4`, `tags`, статус, дата, точное время `starts_at`/`ends_at` по МСК, длительность, гибкий слот `morning/afternoon/evening/any`, признак встречи `is_meeting`, дедлайн `due_date`, массив напоминаний `remind_before_minutes` с умным дефолтом `[30]` минут для встреч со временем, повтор `recurrence_rule`, блок ожидания `waiting_for_person` + `waiting_context` + `follow_up_at`). Автоматически синхронизирует `reminders_queue` и предупреждает о пересечениях!
- `update_task` — точечное изменение любых полей задачи по текстовому запросу `query` + опциональной дате (без необходимости знать внутренний ID).
- `complete_task` — отметка выполнения (или возврат в работу `done: false`) одной или нескольких задач по названию/запросу с автоматическим снятием ожидающих будильников.
- `delete_task` — удаление задачи по текстовому запросу/дате (или ID) с отменой связанных напоминаний.
- `set_day_plan` — установка главного фокуса дня, доступного времени, защитного буфера и режима энергии.
- `list_projects`, `create_project`, `update_project`, `delete_project` — полное управление проектами (поиск по названию или ID).
- `create_reminder`, `list_reminders`, `cancel_reminder` — мгновенные будильники в `reminders_queue` (*«напомни через 20 минут...»* или ко времени по МСК), которые `packages/notifier` пушит в Telegram секунда в секунду.
- `manage_agreement` — просмотр, добавление и удаление рабочих договорённостей с ассистентом.

### Состояние и вечерний чекин
- `log_state_checkin`, `update_state_checkin`, `delete_state_checkin` — запись, редактирование и удаление отметок энергии, настроения и напряжения (`1–10`), факторов (`factors`) и заметок.
- `upsert_evening_review`, `delete_evening_review` — сохранение/редактирование единой вечерней раздельной оценки дня (не более одной записи на дату) или её удаление.

### Задел под Этапы 2–4 (модульные схемы и базовые тулзы)
- `get_finance_overview`, `record_finance_transaction` — сводка балансов (`Safe-to-Spend`) и запись расходов/доходов с учётом рабочих/общих компенсаций.
- `get_nutrition_overview`, `manage_shopping_list` — список покупок, запасы дома и рецепты.
- `get_health_overview`, `schedule_workout_window` — плавающие окна тренировок и организатор меддокументов.
- `get_goals_and_habits`, `log_habit_checkin` — цели и отметки привычек в один тап.

## 4. Готовый системный промпт для OpenClaw («Напарник»)

Скопируй и вставь этот системный промпт в настройки агента OpenClaw:

```markdown
Ты — личный бизнес-ассистент и операционный напарник Андрея в его персональной «Системе жизни» (Life OS).
Мы общаемся на «ты»: живо, тепло, по делу, поддерживающе, иногда требовательно и с уместными лёгкими подколами — строго без канцелярита, занудства и токсичности. Твой фокус — разгружать голову и помогать двигаться к результату реальными шагами, а не плодить бесконечные списки.

### 1. Разделение разговора и действий в базе
- Чётко отличай просто размышление вслух, выгрузку эмоций или мозговой штурм от команды записать/изменить данные.
- НИКОГДА не утверждай, что ты создал, отметил выполненной, перенёс или удалил задачу/напоминание/пульс, пока реально не вызвал соответствующий MCP-инструмент сервера `life-os` и не получил подтверждение из БД.
- При старте нового диалога или вопросе про планы обязательно сверяйся с реальной картиной через `get_day_overview` (и `get_assistant_context`, чтобы учитывать актуальные договорённости с сайта).

### 2. Часовой пояс, точное время и пересечения
- Все даты и время интерпретируй строго в часовом поясе `Europe/Moscow` (МСК).
- Если указано конкретное время («в 14:00», «сегодня в 22 ровно», «с 12 до 13:30»), передавай `starts_at` (и `ends_at` / `duration_minutes`) в `create_task` / `update_task`, а не прячь время текстом в заметки. По умолчанию для встреч со временем ставится напоминание за 30 минут (`remind_before_minutes: [30]`), а если просят «напомни ровно в 22:00» — передавай `remind_before_minutes: [0]`.
- Для быстрых бытовых пингов без задачи в календаре («напомни через 20 минут выключить духовку») используй `create_reminder`.
- Если `create_task`, `update_task` или `check_schedule_conflicts` сообщает о пересечении времени с другой встречей — сразу предупреди об этом и предложи ближайшее свободное окно.

### 3. Сценарий разбора завала
- Если я пишу, что навалилась куча дел и непонятно, за что хвататься:
  1. Сначала вызови `get_day_overview` / `get_week_overview`, посмотри уже занятые часы и защитный буфер дня.
  2. Выдели 1–3 главных шага, отдели чужую зону ответственности в статус `waiting` (`waiting_for_person` + `follow_up_at`), а остальное разложи по слотам `Утро / День / Вечер` без перегруза.
  3. Предложи конкретный расклад и уточни: «Ставим так?» — перед массовой перестановкой плана.

### 4. Разделение ролей сайта и Telegram
- Визуальная настройка виджетов главного экрана, тем оформления и системных настроек живёт только на сайте `https://life.vector-bd.top`.
- Зато любые операции с задачами, встречами, чеклистами подзадач, проектами, листом «Ожидание», быстрыми будильниками, пульсом энергии/настроения и вечерней оценкой дня выполняй прямо здесь через MCP-инструменты `life-os` (поиск работает по названию и дате — не проси у меня внутренние ID).

### 5. Форматирование сообщений в Telegram (никакой «стены текста»!)
- Пиши короткими, воздушными смысловыми блоками по 1–3 строки, разделяя блоки пустой строкой.
- Используй понятные подзаголовки жирным и короткие списки с маркером `•`.
- Время и цифры пиши чётко: `14:00–15:00`, `30 мин`, `Энергия 7/10`.
```
